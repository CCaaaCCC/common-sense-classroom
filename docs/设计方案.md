## 1. 作品定位

**一句话**：用一台平板，把「课堂常规」和「过马路」两件事，拆成孩子能听懂的一句话、看得懂的两张图、点得对的一个按钮。

**使用者**

| 角色 | 特征 | 需求 |
|---|---|---|
| 儿童（4–8 岁，孤独症谱系） | 识字少、注意短、对变化敏感 | 大字大图、语音指令、反馈可预期、不会被误触打断 |
| 家长 / 治疗师 | 陪着操作，事后看数据 | 快速发起训练、看到一次通过率与需要重教的题 |

**不做什么（划清边界，避免无限膨胀）**

- 不做真 AR（uni-app x 无 WebGL/DOM，接 ARCore 原生插件成本不可控）
- 不做硬件固件、不做蓝牙/WiFi 真机联调（协议与接口先留好）
- 不做云同步、不做账号体系、不做多语言

## 2. 教学模型（全项目的核心）

### 2.1 四段式闭环

```
        ┌──────────────── 错第 1 次 ────────────────┐
        │                                          │
TEACH ──┤──> ASK ──正确──> REWARD ──> NEXT ──还有题──> TEACH
（先教）      │                                     │
              └──错第 2 次──> REVEAL ──> NEXT ──无题──> RESULT
                            （公布答案）
```

| 状态 | 做什么 | 时长 | 埋点 |
|---|---|---|---|
| TEACH | 显示教学图 + 播放台词「过马路，走斑马线。」 | 音频结束或 ≤4s | — |
| ASK | 显示题干 + 两个选项卡片，开始计时 | 无上限（不催促） | `startTs` |
| REWARD | 卡片放大 + 星星 + 正确音效 +（将来硬件灯光/舵机） | 1.2s | `ok=true, hint=0` |
| RE_TEACH | 重播教学句 + 高亮正确选项（只高亮不代答） | 2.5s | — |
| ASK（第二次） | 同上，`attempt=2` | — | 若答对 `ok=false, hint=1` |
| REVEAL | 正确选项放大 + 错误选项变灰 + 播「答案是斑马线。」 | 2.5s | `ok=false, hint=2` |
| NEXT | 切下一题或进结果页 | — | — |

**关键规则**

1. **题目顺序固定**，不随机（可预期是这类儿童的安全感来源）
2. **答错不惩罚**：无红叉、无刺耳音效、无「错了」字样；错误色用暖橙 `#F2A65A`，不用纯红
3. **只答两次**，第二次错就直接公布答案并演示正确操作，不无限重试
4. **`hint` 是核心指标**：0 = 一次通过，1 = 重教后通过，2 = 公布答案

### 2.2 设计原则（写进代码注释，评审时可直接引用）

- 一屏只问一件事，选项不超过 2 个
- 所有指令先「说」再「写」，文字只作辅助
- 反馈必须即时（≤200ms），且同一行为反馈永远一致
- 动效只用位移/缩放/透明度，不用闪烁和旋转
- 全局无返回键，退出只能由家长长按触发

## 5. 页面与交互

### 5.1 信息架构

```
pages/home        一级菜单
 ├── pages/setup        场景设置
 │     └── pages/session    学习主流程（状态机）
 │            └── pages/result  结果页
 ├── pages/book        绘本页
 └── pages/parent      家长端（home 右下角长按 5 秒进入）
```

### 5.2 各页面规格

**home**

- 三个大按钮竖排：`开始训练`（主色块，高 88px）、`我的绘本`、底部小字 `已训练 N 次`
- 右下角 72×72px 隐形热区，长按 5000ms 进 parent（按住时显示 36 段进度环，移动超过 20px 取消）
- 无导航栏返回

**setup**

- 场景卡片横排两张（教室 / 过马路），选中态描边
- 题量分段控件：`2 题` / `4 题` / `8 题`
- 开关：`显示文字`、`播放语音`
- 底部主按钮 `开始`；左上角小返回（仅家长陪同使用）

**session**（核心页）

- 顶部：进度 `第 2 / 4 题` + 细进度条
- 中部：教学图 / 题干图（`aspectFit`，高度 300px）
- 下部：两个选项卡片，各占 44% 宽、220px 高，圆角 24px，间距 16px
- 语音播放时：角色图底部 3 根声波条循环起伏；如采用口型方案则切 2 帧嘴型（见 7.3）
- **语音两段**：先播教学句（`teachAudio`），再播问句（`promptAudio`）；问句播完才解锁、才开始计时（`askStart`），此时才给硬件下发 `task`。不识字的孩子全靠这两段语音理解题目
- 正确反馈：卡片 `scale 1.05` + 星星粒子 600ms + 音效（实现说明：受 Vapor 限制，实际为卡片描边 + 静态星星，未做 scale/粒子动画）
- 错误反馈：卡片左右摆动 300ms（`translate` 交替 ±8px，共 3 次）（实现说明：实际为高亮正确项 + 暖色描边，无摆动）
- 全屏无返回；不做家长中止本轮（实现：`onBackPress` 拦截，真机待验）

**result**

- 星级：一次通过率 ≥80% 三星，≥50% 二星，否则一星
- 文案：`这次答对 3 题，需要重教 1 题`
- 错题回顾：列出 `hint >= 1` 的题，点击可重播教学句
- 按钮：`再玩一次` / `看绘本`
- 数据来源：按本轮 `sid` 从存储重算轮次（与家长端共用 `roundsOf`），保证两处题数一致

**book**

- 横向分页（每个场景一页），页内 8 张卡片（2 列，每题一张），点击卡片朗读对应教学句
- 底部圆点页码指示

**parent**

- 三段切换（同页内 tab）：`记录` / `统计` / `设置`
- 记录：按轮分组倒序，每轮显示场景·时间、题数、一次通过率，点击展开逐题标签与反应时；首屏 50 轮，可「加载更多」
- 统计：总题数 / 一次通过率 / 平均反应时、最近 10 轮一次通过率柱图、单题正确率（最差在前）、最近 10 轮历史、导出 CSV
- 设置：音量、显示文字 / 播放语音开关、硬件地址与连接、清空当前孩子记录、重置本地数据（二次确认）

### 5.3 UI 规范

| 项 | 值 |
|---|---|
| 主色 | `#7FB2EF`（沿用现页面） |
| 正确色 | `#4CC38A` |
| 错误色 | `#F2A65A`（暖橙，非纯红） |
| 背景 | `#F6F8FB` |

## 6. 数据结构

```ts
// data/types.uts
export type Option = {
  id: string,        // 'a' | 'b'
  label: string,     // 简短文案，≤8 字
  image: string,     // /static/scenes/{sceneId}/{qid}_{id}.jpg
  correct: boolean
}

export type Question = {
  id: string,        // 'CL-01'
  type: 'identify' | 'judge',
  teachText: string, // 教学句
  teachAudio: string,
  teachImage: string,
  promptText: string,
  promptAudio: string,
  options: Option[],
  answerId: string,
  revealAudio: string
}

export type Scene = {
  id: string,        // 'class' | 'cross'
  name: string,
  cover: string,
  questions: Question[]
}

export type Trial = {
  id: string,
  childId: string,   // 多档案，对应 asd_profiles 中的 id
  sceneId: string,
  qid: string,
  optId: string,
  ok: boolean,       // 一次通过
  hint: number,      // 0 | 1 | 2
  ms: number,        // 反应时（ASK 进入到点击）
  ts: number
}

export type Session = {
  id: string,
  childId: string,
  sceneId: string,
  startTs: number,
  endTs: number,
  trials: Trial[]
}

export type Profile = {
  childId: string,
  name: string,
  avatar: string,
  createdAt: number
}
```

**存储键**（全部 `uni.setStorageSync`，字符串存 JSON）

| 键 | 值 | 上限 |
|---|---|---|
| `asd_profiles` | `Profile[]`，多孩子档案 | 20 条 |
| `asd_active_child` | 当前孩子 id | 1 条 |
| `asd_trials` | `Trial[]` | 2000 条，超出从头截断 |
| `asd_sessions` | `Session[]` | 100 条 |
| `asd_settings` | `{ volume, showText, autoVoice }` | 1 条 |

容量估算：单条 Trial 约 150 字节，2000 条 ≈ 300KB，远低于存储上限，无需分片。

## 7. 技术实现

### 7.1 工具链现状

| 项 | 值 |
|---|---|
| IDE | HBuilderX 5.26.2026091802（已升级） |
| 框架 | uni-app x，`manifest.json` 开启 `vapor: true` + `vapor-render-target: bytecode` |
| 运行目标 | Android 真机（Redmi K70 / Android 16），标准基座 |
| 依赖 | 不引入 npm、不引入 uni-ui 组件、不引状态库 |

### 7.2 状态管理与数据流

- 不用 Pinia（官方版不支持 UTS），采用**官方推荐的独立 `.uts` 全局 `reactive` 单例**（`store/index.uts`）；`globalData`、`globalThis`、`provide/inject` 在 Vapor 下均不可用

```ts
// store/index.uts
export type State = { activeChildId: string, volume: number, showText: boolean, autoVoice: boolean }
export const state = reactive({ activeChildId: '', volume: 0.8, showText: true, autoVoice: true } as State)
```

- **唯一写入口**：`utils/storage.uts` 的 `appendTrial()`，session 页只调它，parent 页只读
- **页面间不用 URL query 传参**：Vapor 下 `onLoad` 不可用，改为 setup 页写 `store.startSession(cfg)`，session 页在 `onMounted` 读取
- 页面生命周期只用 Vue 的 `onMounted`/`onUnmounted`；Vapor 兼容性需 S0 真机验证，失败则关闭 `manifest.json` 的 `vapor`

### 7.3 语音与口型

| 项 | 方案 |
|---|---|
| 播放 | `uni.createInnerAudioContext()`，全局复用 1 个实例，切题时 `stop()` 再 `src` |
| 音频规格 | mp3 / 44.1kHz / 单声道 / 单句 ≤ 3s / 48kbps |
| 预加载 | `setup` 页进入时按所选场景批量 `src` 预热，避免首句延迟 |
| 口型（推荐方案 A） | 角色图不动，底部 3 根声波条按 120ms 变频起伏，播完停止 |
| 口型（方案 B） | 2 帧嘴型（闭/开）按 90ms 交替切换，需美术出 2 张严格对齐的图 |
| 静音兜底 | 设备无声时，全靠文字 + 图片，不影响流程 |

> 选 A 还是 B 需你决定。A 零美术成本、今天可做；B 更像"说话"，但 AI 生成的两帧很难对齐，容易穿帮。

### 7.4 动画实现

- **只用 JS 定时器驱动状态 + CSS `transition`**，不用 CSS keyframes（App 端 `@keyframes`/`animation` 不支持）；`transition` 不能用于 flatten 节点，需要过渡的节点不要加 flatten
- 帧序列（嘴型、声波条）用 `setInterval` 切 `:src` 或 `:style`，组件卸载时 `clearInterval`
- 页面 `onHide` / 离开时统一清理定时器与音频实例

### 7.5 uvue 硬约束（编码时必须遵守）

- 无 DOM API，样式只能靠 `:class` / `:style` 驱动
- 文本必须包在 `<text>` 内；单位只用 `px`
- 条件渲染只用 `v-if`；无 `display: none`
- 布局只有 flex，默认 `flex-direction: column`
- 数组对象类型必须显式 `type` 声明，不能用 `any`

### 7.6 与现有代码的关系

| 现有 | 处理 |
|---|---|
| `pages/index/index.uvue` | 场景数据迁移到 `data/scenes.uts` 后**删除该页** |
| `recs` 按 `sceneId` 去重 | **废弃**，改为 Trial 全量追加（去重会丢训练数据） |
| `pages.json` 单页注册 | 改为注册 7 个页面（含 profiles），`home` 为首屏，均 `navigationStyle:"custom"` |
| `imageOf()` 拼路径 | 改为题目对象里存完整 `image` 字段 |

### 7.7 硬件接口

硬件定位、协议 v1.0、接线与固件设计见 **`docs/硬件开发文档.md`**。要点：

- 硬件只是 App 的外设，**不判对错**；`ok/hint` 由 App 判定
- 设备只上报 `choice{opt, seq}`，App 丢弃重复 `seq`
- 进入讲解阶段必须发 `disarm`，否则误按会打乱 `attempt`
- 未连接时自动回退触屏，训练不受影响

## 8. 指标与报告

| 指标 | 算法 | 用途 |
|---|---|---|
| 一次通过率 | `hint == 0` 的题数 ÷ 总题数 | 结果页星级、家长端主指标 |
| 重教率 | `hint == 1` 的题数 ÷ 总题数 | 判断题目难度是否合适 |
| 公布答案率 | `hint == 2` 的题数 ÷ 总题数 | 超过 40% 说明该题需要重做配图或文案 |
| 平均反应时 | `ms` 的平均值（仅统计 `hint == 0`） | 熟练度趋势 |
| 完成题数 | `trials.length` | 家长端首页概览 |

## 9. 验收标准（3 分钟演示脚本）

1. 打开 App → 一级菜单显示「开始训练 / 我的绘本」
