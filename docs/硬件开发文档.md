| 项 | 内容 |
|---|---|
| 版本 | v1.0 |
| 日期 | 2026-10-25 |
| 定位 | App 的输入/反馈外设，不含题目与判定 |
| 形态 | 纸板沙盘 + 2 个实体按钮 + 红绿灯 + 无源蜂鸣器 + 1 个舵机 |

## 1. 定位与边界

**一句话**：孩子按纸板上的按钮，硬件亮灯、响旋律、弹小旗；对错由 App 判定，硬件不存题、不判分、不记录。

| 硬件负责 | App 负责 |
|---|---|
| 采集左右按钮（去抖、锁存） | 出题、播放教学语音、显示图片 |
| 收到 `task` 后进入可作答状态 | 判定对错，决定 `ok/hint` |
| 收到 `reward` 后亮灯 / 响旋律 / 弹旗 | 记录 Trial、统计与报告 |
| 上报 `choice{opt, seq}` | 计时（`ms` 由 App 算） |
| 断线重连与状态补报 | 断线时静默回退触屏 |

**明确不做**：硬件本地题库、离线判分、语音播报（语音在 App 端）、多设备组网、屏幕。

## 3. 交互时序

### 3.1 正常一题

```
App                          ESP32
 │  disarm (讲解中，禁止作答)   │
 │ ─────────────────────────> │  IDLE
 │  task{sid,scene,qid,idx}    │
 │ ─────────────────────────> │  ARMED（绿灯微亮）
 │                             │
 │                             │  孩子按下左键
 │  choice{sid,qid,opt:"a",seq}│
 │ <───────────────────────── │  LATCHED（短音确认）
 │  判定 ok=true                │
 │  reward{sid,qid,ok:true,hint:0}
 │ ─────────────────────────> │  FEEDBACK（绿闪+上行旋律+弹旗）
 │  task（下一题）              │
 │ ─────────────────────────> │  ARMED
```

### 3.2 答错与重教

| 事件 | App 动作 | 硬件动作 |
|---|---|---|
| 第 1 次错 | 进入 reteach，**不发 reward**，只发 `disarm` | 落回待机，不亮红灯 |
| 重教结束 | 发 `task`（同 qid） | 重新 ARMED |
| 第 2 次错 | 进入 reveal，发 `reward{ok:false,hint:2}` | 红闪 3 次 + 下行三音 |

> 第一次答错**不亮红灯**：与「答错不惩罚」的教学口径一致。红灯只在公布答案时出现。

### 3.3 断线与重连

```
WS 断开 → App 标记离线（触屏继续可用），硬件 20s 无帧回 IDLE、舵机归位
重连    → 硬件发 hello + state；App 回 welcome；若处于 ask 阶段则重发当前 task
```

## 6. 接线表

| ESP32 | 接到 | 说明 |
|---|---|---|
| GPIO32 | 按钮 A 一端 | 另一端接 GND；`INPUT_PULLUP` |
| GPIO33 | 按钮 B 一端 | 同上 |
| GPIO25 | 220Ω → 红灯 → GND | PWM |
| GPIO26 | 220Ω → 绿灯 → GND | PWM |
| GPIO18 | 1kΩ → S8050 基极 | 蜂鸣器串在集电极与 5V 之间 |
| GPIO19 | 舵机橙线（信号） | 舵机红→5V，棕→GND |
| 5V | 降压输出正 | 同时给舵机与 ESP32 5V 脚 |
| GND | 公共地 | **必须共地**，否则 PWM 与 WS 都会异常 |

**接线三条铁律**

1. 舵机电源从降压模块**直接取**，不要从 ESP32 的 5V 排针串过去
2. 舵机电源端并 1000µF，正负极别接反
3. 第一次上电先不插舵机，确认 5V 稳定在 4.9–5.1V 再接

| 件 | 固定方式 |
|---|---|
| 亚克力背板 | 3M 无痕胶贴在纸板背面，不钻孔 |
| 按钮 | 穿过背板开孔（只开背板），帽面高出纸板 3–5mm |

## 9. 固件设计

> 可烧录的完整固件在 `tools/firmware/asd_board/`，本节只讲设计要点。

### 9.1 状态机

```
BOOT → AP_UP → WAIT_CLIENT → IDLE
                                │ task
                                ▼
                             ARMED ──btn──> LATCHED ──reward──> FEEDBACK ──> IDLE
                                ▲                                    │
                                └──────────── task ──────────────────┘
   disarm（任意状态）→ IDLE
   20s 无帧 → IDLE + 舵机归位
```

| 状态 | 允许按键 | 灯 | 舵机 |
|---|---|---|---|
| IDLE | 否 | 全灭 | 0° |
| ARMED | 是（只收第一次） | 绿灯 10% 微亮 | 0° |
| LATCHED | 否 | 绿灯 3 次快闪（已收到） | 0° |
| FEEDBACK | 否 | 对：绿闪；错：红闪 | 对：90° 保持 3s；错：0° |

### 9.2 主循环（非阻塞）

```cpp
void loop() {
  ws.loop();        // 收发，绝不 delay
  btn.tick(millis());
  led.tick(millis());
  buzzer.tick(millis());
  servo.tick(millis());
  hb.tick(millis());
}
```

**禁止**在 `loop()` 里 `delay()`：旋钮按下到上报的窗口只有几十毫秒，`delay(500)` 会直接吞掉按键。

### 9.3 按键去抖与锁存（关键片段）

```cpp
struct Button {
  uint8_t pin; bool stable = HIGH; uint32_t last = 0; bool latched = false;
  bool pressedEdge(uint32_t now) {
    bool raw = digitalRead(pin);
    if (raw != stable && now - last > 25) { last = now; stable = raw;
      if (stable == LOW && !latched) { latched = true; return true; }
    }
    return false;
  }
};
```

- `latched` 在收到 `task` / `disarm` / `reward` 时**都要清零**，否则重教后重新 arm 会按不动
- 锁存期间第二次按下直接丢弃 → 天然防连点

### 9.4 无源蜂鸣器与旋律

无源蜂鸣器**不能用 `digitalWrite`**，必须给 PWM 频率：

```cpp
// Arduino-ESP32 3.x（推荐，固件按此写法）
ledcAttach(18, 2000, 10);
ledcWriteTone(18, 523);   // C5
ledcWriteTone(18, 0);     // 停

// Arduino-ESP32 2.x（老工程）
ledcSetup(0, 2000, 10); ledcAttachPin(18, 0);
ledcWriteTone(0, 523);
```

旋律用步进表，10ms tick 推进：

```cpp
struct Note { uint16_t hz; uint16_t ms; };
static const Note OK[]  = {{523,120},{659,120},{784,120},{784,240}};
static const Note BAD[] = {{392,200},{330,200}};
static const Note REVEAL[] = {{392,180},{330,180},{262,300}};
static const Note TAP[] = {{880,40}};
```

| 事件 | 旋律 | 灯 |
|---|---|---|
| 按键确认 | `TAP` | 绿 3 次快闪 |
| 答对 | `OK` 上行 | 绿闪 3 次（150ms 间隔） |
| 公布答案 | `REVEAL` 下行 | 红闪 3 次 |
| 上线 | `TAP` | 绿灯单闪 |

### 9.5 舵机缓动

```cpp
// 20ms 一拍，每拍 10µs 步进，到位 detach()
void tick(uint32_t now) {
  if (now - lastTick < 20) return;
  lastTick = now;
  if (cur == target) { if (attached) { servo.detach(); attached = false; } return; }
  cur += (target > cur) ? 10 : -10;
  servo.writeMicroseconds(500 + cur * 2000 / 180);
}
```

### 9.6 网络

```cpp
WiFi.mode(WIFI_AP);
WiFi.softAP("ASD-BOARD", "12345678", 6, 0, 2);  // 固定信道 6，最多 2 个客户端
WiFi.setSleep(false);                            // 关省电，否则延迟抖动
```

- WS 库：`links2004/WebSocketsServer`（同步、单客户端足够、`loop()` 非阻塞）
- 发送一律 `char buf[160]; snprintf(...)`，**禁止 `String` 拼接**（长时间运行会堆碎片）
- 心跳：每 5s 发 `ping`；20s 未收到任何帧 → 回 IDLE、舵机归位

## 10. 协议 v1.0

### 10.1 设备 → App

```json
{"t":"hello","id":"esp32-01","fw":"1.0","caps":["btn2","led_rg","buzzer","servo"],"boot":12}
{"t":"state","phase":"armed","sid":"s-1730","qid":"CR-01"}
{"t":"choice","sid":"s-1730","qid":"CR-01","opt":"a","seq":7,"ts":18320}
{"t":"pong","ts":19000}
{"t":"err","code":"SERVO_STALL","msg":"timeout"}
```

| 字段 | 说明 |
|---|---|
| `seq` | 设备自增，App 丢弃重复值 |
| `ts` | 设备开机毫秒，仅用于排序 |
| `phase` | `idle` / `armed` / `busy` |

### 10.2 App → 设备

```json
{"t":"welcome","sid":"s-1730"}
{"t":"task","sid":"s-1730","scene":"cross","qid":"CR-01","idx":0,"total":8}
{"t":"disarm","sid":"s-1730"}
{"t":"reward","sid":"s-1730","qid":"CR-01","ok":true,"hint":0}
{"t":"idle"}
{"t":"ping","ts":1730000000}
```

### 10.3 规则

1. **App 是唯一权威**：设备不判对错，`opt` 只表示左/右。
2. `ms` 由 App 计算（`askStart` 到收到 `choice` 的时间），设备不报时间。
3. 一题只接受一个 `choice`；`LATCHED` 后到 `reward`/`disarm` 之前的按键全部丢弃。
4. 进入 `teach` 必须先发 `disarm`；没有 `task` 时按钮无效。
5. 重连：设备先 `hello`，再 `state`；App 回 `welcome`，必要时重发 `task`。
6. 协议版本不兼容时，App 记录日志并回退触屏，不阻断训练。

## 11. 联调

### 11.1 用模拟器（无硬件）

```bash
cd tools/hardware-sim
npm install
node server.mjs            # WS 默认 8081，HTTP 按钮板默认 8082
WS_PORT=9001 node server.mjs   # 端口被占用时改 WS 端口
```

| 操作 | 说明 |
|---|---|
| 键盘 `a` / `b` | 模拟左/右键 |
| 键盘 `r` | 补发一次 reward（调试灯效） |
| 键盘 `p` | 模拟掉线 |
| 键盘 `s` | 打印当前状态 |
| 浏览器 | `http://<PC-IP>:8082` 两个大按钮，适合手机点 |
| `GET /press?act=a\|b\|reward` | 命令行/脚本触发，便于自动化测试 |

App 端：家长端 → 设置 → 硬件 → 填入 `PC 局域网 IP:8081`（例如 `192.168.1.109:8081`）→ 连接。模拟器启动时会把本机所有 IPv4 打印在控制台。

### 11.2 真机

1. 上电，手机搜到 `ASD-BOARD` 并连接（提示「无互联网」时选**保持连接**）
2. **关闭移动数据**，或关闭「WLAN 助理 / 自动切换移动数据」
3. App 家长端填入 `192.168.4.1`，状态变绿
4. 开始训练，按纸板按钮

### 11.3 Windows 防火墙

首次运行 `node server.mjs` 会弹窗，必须允许「专用网络」；否则手机能连 WiFi 但连不上 WS。

### 11.4 联调实测（2026-10-25，真机 + PC 模拟器）

| 用例 | 结果 |
|---|---|
| V1 连接 | 通过。手机 `192.168.1.199` → PC `192.168.1.109:8081`（模拟器默认端口），`hello`→`welcome`，设置页状态点变绿 |
| V2 讲解阶段按键 | 通过。`phase=idle`，按键被丢弃，App 不产生记录 |
| V3 答对 | 通过。`task` → 按键 → `choice` → `reward{ok:true,hint:0}`，往返 **128ms** |
| V4 连错两次 | 通过（**修正原预期**）：第 1 次错只发 `disarm`、不亮红灯；重教后重新 `task`；第 2 次错发 `reward{ok:false,hint:2}` → 红灯 + 下行旋律 |
| V5 掉线 | 通过。杀掉模拟器后 App 标记离线，触屏可继续完成下一题，无崩溃 |
| V6 重连 | 通过。模拟器重启后 App 自动重连，并**自动重新下发当前题**，不跳号 |

**联调中修掉的三处实现问题**

1. `onError` 不会触发 `onClose`（socket 未建立时），必须两处都重连
2. `task` 抢在 `welcome` 之前发出 → 把「重发当前题」移到收到 `hello` 之后
3. 中文输入法会把半角冒号打成全角、并在数字后插空格 → 地址解析统一 `trim` + 全角转半角

> 排障提示：「1 秒一次断线重连」的根因已在 App 端修掉（`utils/device.uts` 增加连接代次，重复 `connect()` 幂等返回、旧 socket 回调按代次丢弃）。若仍复现，先确认手机端没有同时跑旧版本。

### 11.5 本轮稳定性修正（2026-10-30）

| 问题 | 根因 | 修正 |
|---|---|---|
| 1 秒一次自我重连 | `connect()` 在已连接时再次调用 → 关旧 socket → `onClose` 触发 `scheduleRetry` → 关掉刚连上的 socket | 连接代次 `gen` + 同地址幂等 + `doConnect` 前清 `retryTimer` |
| 设备重启后前几次按键被吞 | 固件 `gSeq` 断电归零，App 的 `lastSeq` 门槛还在 | 收到 `hello`（重连）时 `lastSeq=0` |
| 手动断开后回首页又被连上 | home 挂载无条件 `connect()` | 持久化 `autoConnect`，断开置 false、手动连接置 true |

## 13. 故障排查

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 搜不到热点 | 供电不足 / 代码未进 AP 模式 | 测 5V；看串口是否打印 AP 启动 |
| 连上但 App 连不上 | 手机切回移动数据；防火墙拦截 | 关移动数据；放行 node/防火墙专用网络 |
| 按键无反应 | 用了 `INPUT` 而非 `INPUT_PULLUP`；未 arm | 改上拉；确认收到 `task` |
| 一次按键触发两次 | 监听重复注册 / 未锁存 | 检查 App 单例；固件 `latched` |
| 蜂鸣器只「嗒」一声 | 买了**有源**蜂鸣器 | 换无源，或改 GPIO 高低电平驱动 |
| 舵机抖动 / ESP32 重启 | 舵机与主控共用 5V、无电容 | 独立取电 + 1000µF |
| WiFi 频繁掉线 | `WiFi.setSleep(true)` 或供电跌落 | 关省电；查电压 |
| 灯常亮不闪 | 用了阻塞 `delay` 做闪烁 | 改 tick 状态机 |

## 14. 风险与后续

| 风险 | 影响 | 对策 |
|---|---|---|
| 现场没有可用的 2.4G 环境（热点本身不受影响） | 低 | ESP32 自开热点，不依赖场地路由 |
| 纸板承重不足 | 按钮按下时纸板变形 | 亚克力背板承力，纸板只做外观 |
| 单舵机无法区分场景奖励物 | 演示表现力 | 文档已说明；后续加第二个舵机（GPIO21） |
| 孩子连续猛按 | 机械寿命 | 街机按钮 10 万次以上；固件锁存防抖 |

**后续可扩展**：第二个舵机做「教室小旗 / 马路小车」、加一路触摸传感器、把 `caps` 扩展成能力协商。
